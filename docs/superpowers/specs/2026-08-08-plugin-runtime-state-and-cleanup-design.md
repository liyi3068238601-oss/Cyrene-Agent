# 插件运行状态与完整卸载修复设计

## 目标

修复两个问题：

1. 插件启动失败时，设置页不能继续显示“已启用”。
2. 用户关闭插件时，必须等渠道适配器完全停止后再返回成功。

## 设计

### 运行状态

设置页现有的 `enabled` 字段继续保留，但它改为表示“插件现在是否真实运行”。只有插件实例已经成功注册时，`enabled` 才为 `true`。

如果插件启动失败：

- `enabled` 返回 `false`；
- 持久化的启用偏好不被悄悄篡改，下次启动仍可再次尝试；
- 用户在设置页再次点击启用时，管理器必须重新执行启动，不能因为配置里原本是 `true` 就直接返回成功。

这样不需要修改 preload、设置页类型或按钮文案。

### 完整卸载

插件上下文的 `dispose()` 改为异步方法。它会先清理同步资源，再等待所有已注册的渠道适配器完成 `unregister()`。

以下调用链都必须等待 `dispose()`：

- 插件 `register()` 失败后的回滚；
- 用户禁用插件；
- `PluginManager.stop()` 停止全部插件。

## 测试

采用测试先行：

1. 新增“首次启动失败后显示停用，再次启用会重试并成功”的管理器测试。
2. 新增“`dispose()` 返回 Promise，并等待渠道注销完成”的上下文测试。
3. 先确认新测试在旧实现上失败，再实现修复。
4. 修复后运行插件专项测试、渠道测试、主进程构建和完整构建。

## 范围

本次不新增插件状态枚举、错误详情字段、插件协议版本或新界面。施工结果追加到现有插件系统计划文档，并分别提交代码与文档。
