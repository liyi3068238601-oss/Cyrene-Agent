# Cyrene 启动前自动构建设计

## 目标

让仍在持续开发 Cyrene 的用户只需双击 `start.bat`，就能先把当前源码完整构建为最新 `dist`，再启动 Electron。这样合并或修改源码后不会误启动旧构建，也不需要用户记住额外的 npm 命令。

## 启动流程

1. BAT 切换到项目根目录，并检查 `npm.cmd` 与 `node_modules`。
2. 环境满足后显示清楚的中文提示，执行 `call npm.cmd run build`。
3. 构建成功后再执行 `call npm.cmd start`。
4. 构建失败时保留 npm 的错误输出，显示“构建失败”与错误码，暂停窗口并退出；禁止继续启动旧 `dist`。
5. Electron 启动失败时继续沿用现有错误码、中文提示和暂停行为。
6. 正常关闭 Cyrene 后，BAT 窗口正常结束。

## 文件与边界

- 修改根目录 `start.bat`。
- 修改 `src/shared/start-bat.test.ts`，用静态契约测试固定“先构建、后启动”和构建失败处理。
- 更新现有启动施工文档 `docs/superpowers/plans/2026-08-08-one-click-start-bat.md`，记录本次行为变更、验证结果和提交。
- 不修改 `setup.bat`、npm scripts、应用源码或依赖版本。
- 不自动执行 `npm install`；缺少 `node_modules` 时仍提示先运行 `setup.bat`。

## 错误处理

- 未找到 npm：提示安装 Node.js 24，暂停并退出 1。
- 未找到依赖：提示运行 `setup.bat`，暂停并退出 1。
- 构建失败：保存构建命令的 `%ERRORLEVEL%`，显示中文错误与该错误码，暂停并原样退出。
- 启动失败：保存启动命令的 `%ERRORLEVEL%`，显示中文错误与该错误码，暂停并原样退出。

## 测试与验收

1. 先修改 `src/shared/start-bat.test.ts`，要求 BAT 包含 `call npm.cmd run build`，并断言构建命令位于启动命令之前。
2. 测试要求构建错误码被单独保存，并存在构建失败分支；在旧 BAT 上应因缺少这些行为而失败。
3. 修改 `start.bat` 后复跑专项测试，确认测试转绿且 CRLF 约束仍成立。
4. 运行 `npm.cmd run build`，确认完整构建成功并生成 NovelAI 必需产物。
5. 运行全量测试，确认其他功能没有回归。
6. 不在自动验证中长时间启动 Electron GUI；BAT 的启动命令和错误分支由静态契约测试覆盖。

## 使用体验与已知代价

- 每次启动都会完整构建，即使源码没有变化也不跳过。
- 当前完整构建约增加二十秒等待时间，终端会显示构建进度。
- 构建会刷新 `dist` 生成文件，Git 可能显示生成物变化；这属于当前开发期的预期行为。
- 项目进入稳定使用期后，可以另行设计“仅源码变化时构建”或独立开发启动脚本，本次不提前增加这些复杂度。
