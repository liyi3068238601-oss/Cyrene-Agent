# NovelAI 新手友好界面设计

日期：2026-08-09
状态：设计已确认，等待文档复核

## 1. 背景

现有 NovelAI 插件已经具备提示词、角色、服装、参考素材、高级生成参数、任务和历史记录等完整功能，但大量控件同时出现在主界面，新用户难以快速判断应该先做什么。

本次改造的目标不是增加生成能力，而是重新组织现有界面，让第一次使用的人能自然完成“描述画面 → 选择角色和服装 → 开始绘制”。

## 2. 已确认的设计方向

- 布局采用“专注画布”：左侧创作步骤，右侧大幅结果预览。
- 视觉采用“暖白画室”：米白背景、浅色卡片、柔和暖橙色主按钮。
- 主界面只保留生成流程；角色、服装和参考素材通过“素材库”进入，API 连接通过“设置”进入。
- 任务和历史记录默认折叠为底部状态栏。
- 中文画面描述与翻译后的英文提示词继续同时显示。
- 高级生成参数保留，但默认折叠。
- 采用低风险重排方案：尽量复用现有元素标识、事件处理和生成逻辑，不在本次进行大规模业务代码重写。

## 3. 页面结构

### 3.1 顶部区域

顶部提供页面名称和两个低频入口：

- “素材库”：管理角色、服装和参考素材。
- “设置”：配置 NovelAI API 连接。

这些功能不再与生成步骤并列显示，避免新用户误以为必须先理解全部模块。

### 3.2 左侧创作区

左侧创作区按顺序呈现三个主要步骤：

1. 描述画面
   - 输入中文自然语言描述。
   - 显示系统翻译后的英文提示词。
   - 两者都允许用户检查和编辑，沿用现有提示词处理能力。
2. 选择角色与服装
   - 展示当前已选角色和服装。
   - 允许不选择，直接进行普通绘图。
   - 详细管理动作通过“素材库”完成。
3. 开始绘制
   - “开始绘制”是页面唯一的高强调主按钮。
   - 点击后显示提交状态，并将任务进度同步到底部状态栏。

### 3.3 高级设置

高级设置位于创作区内，默认折叠。它继续提供现有参数：

- 模型
- 图片宽度和高度
- 步数
- CFG
- 采样器
- 种子
- 参考图模式和相关编辑能力
- 变体数量等当前已有选项

折叠只改变信息展示层级，不改变参数默认值、校验或提交方式。

### 3.4 右侧画布

右侧是页面的视觉中心，用于展示：

- 空状态和简单引导语
- 正在生成的状态
- 最新生成结果
- 必要的结果摘要
- 常用结果操作：下载图片、打开保存目录、沿用当前设置再次绘制

已有画布工具和结果检查能力应保留，但次要工具降低视觉强调，避免与主生成流程争夺注意力。

### 3.5 底部任务抽屉

任务与历史记录默认收起为一条简洁状态栏，显示当前任务状态或最近结果摘要。点击状态栏后展开完整抽屉，查看任务队列和历史图片；再次点击可以收起。

当任务状态变化时，折叠状态栏应提供足够的状态反馈，用户不需要一直打开任务列表。

## 4. 素材库与设置

“素材库”和“设置”使用 NovelAI 主窗口内的独立页面呈现，不使用弹窗，也不新开操作系统窗口。进入这些页面后，通过明确的“返回创作”按钮回到生成界面。

### 4.1 素材库

素材库包含三个分区：

- 角色管理
- 服装管理
- 参考素材管理

用户完成选择或管理后可以返回创作界面，当前提示词与生成参数不应丢失。

### 4.2 设置

设置页承载现有 NovelAI API 连接功能，包括凭据输入、连接状态和已有验证动作。关闭设置后返回原来的创作状态。

## 5. 视觉语言

- 页面主背景使用温暖米白色。
- 内容卡片使用白色或浅奶油色，配合轻微阴影、细边框和适度圆角。
- 主按钮使用柔和暖橙色；其他按钮使用低强调中性色。
- 主文字使用深灰色，辅助文字使用浅灰褐色。
- 成功、等待、警告和失败状态同时使用图标、颜色与简短文字，不能只依赖颜色区分。
- 控件间距、字号和点击区域保持舒适，优先保证普通桌面窗口和较小窗口下的可用性。
- 不追求强烈装饰效果，画布和生成结果始终是视觉重点。

## 6. 交互与状态流

标准生成流程如下：

1. 用户输入中文画面描述。
2. 系统按照现有逻辑生成英文提示词并保持可见。
3. 用户可选择角色和服装，也可以跳过。
4. 用户按需展开高级设置并调整参数。
5. 用户点击“开始绘制”。
6. 主按钮进入提交状态，底部状态栏显示任务进度。
7. 生成完成后，最新图片自动显示在右侧画布。
8. 用户可以下载、打开保存目录、再次绘制，或展开底部抽屉查看历史记录。

切换素材库、设置或底部抽屉时，不应清空当前输入、选择和高级参数。

## 7. 错误处理

- API 未连接时，在生成按钮附近显示“API 尚未连接”，并提供进入设置的明确入口。
- 表单参数无效时，在对应字段附近显示简短说明。
- 任务提交或生成失败时，在画布和底部状态栏显示易懂的失败摘要与重试入口。
- 原始错误、堆栈或服务响应等技术详情放入可展开区域，默认不直接占据主界面。
- 素材加载失败时，不影响基础文本生成流程，并说明受影响的具体素材类型。

## 8. 技术边界

本次改造范围仅限 NovelAI 插件的渲染界面和必要的界面状态连接：

- 调整 `src/renderer/novelai/index.html` 的信息结构。
- 调整 NovelAI 相关 CSS，建立暖白主题、主布局、折叠面板和响应式表现。
- 在现有渲染逻辑中补充高级设置、素材库、设置页和底部抽屉所需的显示状态。
- 尽量保留现有 DOM 标识、数据字段和事件路径，降低回归风险。
- 不改变生成服务、插件运行协议、任务协议和持久化数据格式。
- 不在本次进行与界面目标无关的重构。
- 不提交 `dist` 构建产物。

## 9. 验证与验收

### 9.1 功能验证

- 中文描述输入和英文提示词生成、显示、编辑正常。
- 角色与服装选择正常。
- 参考素材与参考图编辑能力可从新入口访问并正常工作。
- 模型、尺寸、步数、CFG、采样器、种子和其他高级参数提交正常。
- API 连接设置、状态显示和验证动作正常。
- 生成任务提交、进度、失败与完成状态正常。
- 最新结果、下载、打开目录、再次绘制和历史记录正常。
- 在素材库、设置、创作区和任务抽屉之间切换时，当前创作状态不丢失。

### 9.2 界面验证

- 初次打开时，用户能直接识别三个主要步骤。
- 高级参数和低频管理功能默认不会干扰主流程。
- 普通窗口及较小窗口下，主要输入框、生成按钮、画布和状态栏不会被遮挡。
- 加载、空状态、成功和失败状态均有清晰反馈。
- 键盘焦点、按钮文字和必要的可访问性标签保持可用。

### 9.3 工程验证

- NovelAI 渲染代码能够正常构建。
- 执行项目现有相关测试和完整构建检查。
- 人工走查一次“输入描述 → 选择素材 → 生成 → 查看结果 → 查看历史”的完整路径。
- Git 提交中不包含已有的 `dist/renderer/react/index.html` 修改或 `dist/renderer/novelai/` 构建目录。

## 10. 完成标准

当新用户不阅读说明文档也能顺利完成首次绘图，且现有 NovelAI 功能没有因界面重排而丢失或失效，本次改造即可视为完成。
