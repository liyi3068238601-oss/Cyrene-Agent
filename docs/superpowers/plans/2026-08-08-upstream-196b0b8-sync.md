# 上游 196b0b8 同步实施计划

> 目标：让 `liyi-Cyrene-v2` 吸收官方 `master@196b0b8`，同时完整保留本地插件系统、NovelAI 插件、启动脚本和已有文档。

## 原则

- 官方 `master` 只作为上游基线，不把开发分支反向合并进 `master`。
- 发生冲突时以官方的新模块结构为骨架，把我们的功能逐项迁入，禁止整文件粗暴选择一边。
- 主工作目录已有的 `dist` 改动属于用户现场，不修改、不清理。
- 每个可独立核验的阶段单独提交，并在施工记录中留下命令和结果。

## 施工步骤

### 1. 建立基线

- 检查隔离工作树、分支和工作区状态。
- 连接现有 `node_modules`，避免重复下载大量依赖。
- 在临时用户目录下运行同步前测试，记录基线结果。

### 2. 合并官方 master

- 在 `sync/upstream-196b0b8` 执行 `git merge --no-ff master`。
- 预期处理两个内容冲突：
  - `src/main/index.ts`
  - `src/renderer/settings/settings.ts`
- 检查五个自动合并文件，确认两边功能都在：
  - `package.json`
  - `src/preload/index.ts`
  - `src/renderer/settings/index.html`
  - `src/shared/ipc-channels.ts`
  - `vitest.config.ts`

### 3. 按新架构接回插件功能

- 把插件启用状态迁入官方的新设置模块：类型、默认值、读取和归一化都保留。
- 把插件管理器的启动、工具注册、IPC、LLM 能力和退出清理接入官方的新主进程结构。
- 将我们的“功能插件”设置页拆成独立模块，避免覆盖官方已有的天气/旅行/MCP 插件页。
- 保留 NovelAI 插件的注册、设置窗口、工具、IPC 和构建产物。
- 为迁移点补充或调整测试，先确认测试能发现缺失，再实现修复。

### 4. 全面复核

- 搜索未解决冲突标记。

- 对编译后的 NovelAI 插件做无界面运行冒烟测试，确认注册和退出清理正常。

### 5. 合回开发分支并推送

- 更新施工记录，写明测试数量、构建结果和提交号。
